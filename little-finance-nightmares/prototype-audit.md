# 第一版原型審查

**性質：** 技術與設計檢視；不是學生玩家測試。  
**證據標籤：** `prototype_observation`（兩關流程與網頁操作）、`hypothesis`（學習風險）。

## 已觀察到的功能

- Godot 4.7.2 Web 匯出可在本機 HTTP 伺服器載入；兩關均能由理財台作答、取得鑰匙、開門。
- Godot 自動流程測試通過：門鎖限制、提示和答錯扣分、兩關切換、成果畫面。
- Blender 5.3 產生兩張 3D 場景圖與一個鑰匙 GLB；遊戲目前以渲染場景圖呈現，不是即時 3D 場景。

## 尚未證明的教學主張

| 主張 | 目前證據 | 下一步可否證測試 |
| --- | --- | --- |
| 玩家學會需要、想要與儲蓄的取捨 | 只有單題通關與分數 | 以不同數值的同類遷移題比較遊玩前後的選擇與理由 |
| 玩家能理解投資風險 | 只有一題明顯錯誤選項 | 用兩個都看似合理的方案，觀察是否保留近期必需費用並說出理由 |
| 第二關分數較高代表進步 | 兩關考不同概念，不能直接比較 | 分別在同一能力下設計等值前後題，並報告各能力變化 |
| 認知負荷適當 | 未有目標年齡玩家資料 | 觀察首次行動、題幹重讀、求助、誤點與完成後的口頭解釋 |

## 待修正風險

1. 原型答錯後只扣分，仍可用刪去法通關；分數可能獎勵猜測速度而非理解。
2. 每關只有一題，缺少等值的前後題；目前「進步」只是兩關遊戲分差。
3. 手機橫向及鍵盤焦點未做實際代表尺寸檢查。
4. Blender 藝術資產由 `bpy` 腳本產生，尚未依 `blender-skills` 的具體技能流程建立審查與輸出紀錄。

## 形成性試玩建議

- 對象：經教師或家長同意的目標年級學生；不在遊戲中收集姓名。
- 任務：獨立完成兩關，完成後說明一次「先保留必需費用」的理由。
- 記錄：首次可行操作時間、各題重試與提示、正確理由、是否依賴猜測、是否能在不同數值情境遷移。
- 決策規則：若多數玩家在沒有提示時無法解釋正確選擇，或頻繁亂猜，回到玩法與題目設計；若視覺提示使玩家找不到互動點，先修正介面再測學習。

尚未執行學生試玩；不得把以上建議寫為完成的測試結果。
