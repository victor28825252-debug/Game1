# 專案簡報（草案）

**狀態：** 待開發者核准；不得視為 DT handoff 已通過。  
**日期：** 2026-11-24  
**決策擁有者：** 專案使用者／教師。

## 目標

以兩關、網頁可玩的原創暗色童話探索遊戲，讓小學生練習生活預算、儲蓄及投資風險的判斷。場景與模型由 Blender 製作，正式遊戲由 Godot 輸出網頁版本。

## 使用者與情境

- 已確認：小學生；可能在課堂、家中或教學展示時使用，實際使用情境尚待確認。
- 設計假設：先以國小四至六年級閱讀及數量理解能力製作；需由教師確認。
- 利害關係人：學生、教師、家長。教師應能了解題目、評分規則及學習成效的限制。

## 證據、痛點與問題陳述

- 使用者要求兩關、答題取鑰匙、每關得分及結尾進步成果；這是需求證據，尚非玩家需求訪談。
- [美國 CFPB 國小金融教育課程檢核工具](https://files.consumerfinance.gov/f/documents/cfpb_youth-financial-education-curriculum-review-tool.pdf)涵蓋花費取捨、預算、儲蓄及投資的年齡相應概念。
- [CFPB 國小教學指引](https://files.consumerfinance.gov/f/documents/cfpb_pedagogy_elementary-school_handout.pdf)建議使用貼近生活的選擇、比較方案與重複練習。
- [EU／OECD 兒少金融能力框架](https://www.oecd.org/en/publications/financial-competence-framework-for-children-and-youth-in-the-european-union_bf059471-en.html)把規劃財務及風險與報酬列為兒少金融能力範疇。
- 原型觀察：目前每關僅一題，答錯後可重試，可能靠排除法取得鑰匙；結尾把不同概念的兩關分數相減，不能直接推論學習增長。尚無實際學生使用資料。

**問題陳述：** 如何讓小學生在短時間的探索遊戲中做出可解釋的理財選擇，並讓教師看見可重算、可解釋的學習練習結果，而不把遊戲分數誤稱為已證實的學習成效？

## 輸入、處理與輸出

- 輸入：玩家在兩關中的選擇、重試、提示使用及可選的理由回答；不收集姓名或聯絡資料。
- 處理：固定規則判斷選擇與理由，記錄每關正誤、提示及嘗試次數，按公開規則計分。
- 輸出：每關分數、鑰匙與門鎖狀態、結尾兩項能力摘要，以及與同類題目相比的進步指標（若有可比較的前後測題）。

## AI 角色與權限

- AI 協助產生並預評遊戲候選方案；所有預評明確標為 `ai_pre_score`。
- 玩法、視覺、釋出與最終驗收由使用者／教師決定。
- 遊戲執行時由固定 Godot 規則計分，不由 LLM 即時生成或修改分數。

## MVP 與非目標

- MVP：兩個原創場景；每關一個明確互動單元；理解後才取得鑰匙；每關分數；結尾回饋；可在 GitHub Pages 上運行的 Godot Web 匯出。
- 非目標：真實投資交易、金融商品推薦、登入系統、個資收集、照搬參考遊戲角色或素材、宣稱一輪遊玩能證明長期理財能力。

## 限制與風險

- 視覺氛圍可參考暗色童話，但需避免不適合國小生的恐怖、暴力及受保護素材。
- 圖文需要保持可讀；互動需可用滑鼠及鍵盤，盡量支援觸控。
- 投資概念必須以年齡相應的風險理解為主，不鼓勵借貸或追逐保證獲利。
- 現有 Godot WebAssembly 約 40 MB，首次載入速度需驗證。

## 交付情境

現有 Git 遠端為 `Game1`。暫定保留其首頁，將新遊戲以 `/little-finance-nightmares/` 子路徑發布；正式對外發布前，需確認玩法、視覺與版本。

## 成功指標與驗收例子

1. 每關需完成該互動單元並取得鑰匙，未持鑰匙不得開門；Godot 自動測試通過。
2. 每關分數可由選擇、重試及提示記錄重算；結尾清楚區分「遊戲表現」與「學習證據」。
3. 在桌機及手機橫向視窗中，題幹與操作可辨識並可完成兩關。
4. 形成性玩家測試：至少觀察玩家能否說出選擇理由、是否靠猜測、是否因題幹或介面卡住；無實測前不得聲稱已達學習成效。
